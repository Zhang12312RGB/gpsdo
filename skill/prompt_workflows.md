# 提示词工作流（Prompt Workflows）

> **适用场景**：用大模型做 FPGA / 嵌入式工程，需要它给出「可验证」的判断而不是泛泛建议
> **使用方法**：选模板 → 填 `<>` 占位 → **先把`【已排除】`填满** → 再发问
> **共同前提**：一次只问一个层次（协议层 / 算法层 / 工程状态层），混着问必然得到泛泛答案

---

## 模板 1　审查 RTL 状态机

**适用**：写完或改完一个 FSM，怀疑有死角、缺分支、单周期冲突。

```
请审查下面这段 Verilog 状态机，只回答四件事：
1. 有没有【不可达状态】或【缺 default】？
2. 有没有【同一周期两个非阻塞赋值写同一寄存器】（优先级冲突）？
3. 每个状态在【输入不变】时会不会卡死？列出会卡死的状态与条件。
4. 复位后第一个周期各输出是什么电平？与「空闲态」是否一致？

【模块职责】<一句话>
【代码】
<整个 always 块 + 相关的 reg / wire 声明>

【已排除】<我检查过什么>
```

**已验证效果**：本项目用它发现 `uart_rx` 的 re-arm 守卫「armed 清零优先于置位」写反，
以及 `S_START` 缺「起始位校验失败」的返回路径。

**失效条件**：跨模块的时序（跨时钟域、握手）它看不出来，必须单独问。

## 模板 2　从综合报告定位瓶颈

**适用**：资源超了、频率上不去、或者怀疑某个改动带来了资源暴涨。

```
下面是 Vivado 的 utilization / timing 报告节选。请：
1. 指出占用【最异常】的 3 类资源，并说明哪些设计习惯会导致这种比例。
2. 若我要把它压到 <50%，按【收益/风险】排序给出 5 条改法。
3. 对每条改法，给我【一条可以在报告里验证成效的指标】。

【报告节选】
<粘贴 Slice Logic / Memory / DSP 表格 + 最差路径 slack>

【设计概要】<关键模块一句话 + 时钟频率>
【已排除】<试过什么>
```

**已验证效果**：本项目靠「寄存器数与逻辑数比例异常」发现 `uart_rx` 里有 10416 位的移位寄存器，
改完后 FF 从约 11800 降到 **1449（4.12%）**。

**失效条件**：报告是 OOC 综合的（不含顶层布线），面积偏乐观，扇出/布线延迟问题看不到。

## 模板 3　串口 / 协议排查（四栏法，最重要的一个）

**适用**：串口收不到、收到乱码、帧错、协议不响应。

```
【现象】<一句话，带具体数值，不要写「不工作」>
【数据】<原始寄存器值 / 十六进制字节流 / 日志段落，不加工>
【代码】<只贴相关函数或 always 块，带行号区间>
【已排除】<我试过什么、结果如何>

请给出【可能性排序】，每条必须包含：
  - 如果是它，用什么【最便宜的办法】能证实/排除（最好是一行打印或读一个寄存器）
  - 不要直接给结论，我要自己验证
```

**已验证效果**：见 `pitfalls.md` A-3 —— 这个模板暴露了「模型给了单一结论」的风险，
迫使它给出多条假设，最终由一次**波特率扫描**推翻它的首选假设。

**失效条件**：`【已排除】`留空时，它会有一半篇幅建议你已经做过的事，效率骤降。

## 模板 4　控制律稳定性审查（数学层）

**适用**：写了 PI / 卡尔曼 / 自适应，需要确认「会不会振荡/发散」。

```
我的控制律是：<公式>
被控对象模型是：<公式，含增益符号与量纲>
采样周期：<T>

请：
1. 推导闭环递推式，给出【特征根】。
2. 给出【收敛的参数条件】（例如 0 < g/S < 2）。
3. 指出【符号搞反会怎样】—— 我需要确认这是正反馈还是负反馈。
4. 给出【一个数值算例】，展示参数取错会发散到什么程度。
```

**已验证效果**：本项目据此发现绝对式 DAC 律的特征根是 `−g/S`，`g/S = 1000` 时**一拍放大 1000 倍**，
与台架实测「从 +100 ppb 甩到 −83100 ppb」完全吻合。

**失效条件**：模型只能验算**你给的模型**。若被控对象模型本身错了（如把 EFC 极性搞反），它不会提醒你。
**必须自己上板实测增益符号。**

## 模板 5　把结论整理成报告骨架

**适用**：已经跑通、有一堆结论，需要变成可提交的文档结构。

```
这是竞赛的提交要求原文：<粘贴 3.3.5.3 等章节>
这是我手上的材料清单：<列要点，不用全文>

请：
1. 把材料映射到要求的每一个小节，标出【已齐】/【缺】/【需补测】。
2. 对每个缺的项，给出【最小可交付内容】是什么（不要建议扩写）。
3. 指出哪 2~3 项是【评审最可能追问】的，需要提前准备证据。
```

**已验证效果**：本项目用它把 7 张图与 7 个报告小节对齐，并识别出
「板上实测数据」是唯一有硬门槛性质的缺口。

**失效条件**：要求原文没贴全时，它会对缺失部分编造小节名。

## 通用纪律（比模板更重要）

| # | 纪律 |
|---|---|
| 1 | **一次只问一个层次**，混着问必然泛泛 |
| 2 | **`【已排除】`必须填满**，这是效率的分水岭 |
| 3 | 让它给**可能性排序 + 判别方法**，不要它直接下结论 |
| 4 | 拿到结论后，**先挑最便宜的一条自己验证** |
| 5 | 验证结果（尤其是否定）要**回贴给它**，让它在正确前提上继续 |
| 6 | 任何「参数不匹配」类结论，先排除**边界/时序**问题 |
