# 最终固件上板功能验收操作

本验收只检查提交固件的配置、状态切换、DAC冻结及慢环参与，不用于计算OADEV。全程保存同一份原始串口日志，建议文件名 `board_acceptance_20261102.dat`。另有正式性能采集时，应另开文件。

## 0 准备与下载

1. 调试串口设为115200、8N1，选择“保存接收原始文本”。在下载/运行ELF之前开始保存，才能记录启动配置。一个COM口同一时刻只用一个接收软件。
2. 用配套PL硬件和 `board/firmware/gpsdo_final_c.elf`。本次冻结文件的SHA256为 `29717ca20361051e5f3f7cf1d936760821ac88e9ee63a9da41a89c0d7fc2b7e9`，BUILD为 `Nov  2 2026 15:29:18`。不要选R标定版、MODE0回退版或仅凭TRY文件名判断版本。
3. 本次默认固件采用与v27启动记录匹配的重编译文件，TRY源码29文件与提交源已核对一致。上板下载仍由操作者执行。独立重编译产生不同BUILD是正常的；若改用重编译文件，必须同时记录其真实BUILD和SHA256，不冒称上述冻结文件。
4. 保持现有供电和数字接线，接好GNSS天线。KEY1为MIO50，KEY2为MIO51。不要在2秒内连续按两次KEY1：双击会强制回TUNING。

## 1 启动配置核对

必须保存下面三类启动行，字段以实际串口文本为准。

```text
===== BUILD Nov  2 2026 15:29:18 =====
KFCONF profile=1 QF_e9=100000 p3floor=0 fixed_period=1 phsg=0 slow_mode=2
CFCONF scale_u=100000 cap_u=100000 rise_s=300 age_max_s=330 lag_max_s=630
FINALCONF release=FINAL_C_R80_T10_20261031 R_ns2=80 R_train=0 period_fixed=1 phase=0 slow=2
```

正常接收后，应出现TUNING、fix=1、sat≥4和 `NMEA chk ... fresh=1`；观察ok计数持续增加。sat≥8不是状态机的硬门槛。正常快照应为 `SAMP why=0 acc=1`。稳态Tu为10秒，used=1只出现在真实KF/DAC更新拍，其余正常秒used=0。启动第一秒NO_MEAS或尚未收到GGA时fresh=0要单列，不能把它当成整段故障。

先记录至少1分钟连续正常数据，再进行按键操作。此处验证功能，不要求强等到DAC=1886，也不能用X[1]接近0作为绝对频率准确度证明。

## 2 CALIB冻结检查

1. 单击KEY1一次，等到 `STATE -> CALIB` 和连续 `[CALIB]` 行。
2. 记第一条完整CALIB状态行中的 `dac=` 为D0。D0可以是当前实际码值，不必设为1886。
3. 保持60秒，不再按KEY1。CALIB期间每条 `dac=` 均应等于D0，REFCHK仍应逐秒输出，ms和seq推进。
4. 同秒REFCHK.D是快照采样时的码，状态行dac是该状态行时的命令码。状态切换边界需看先后顺序；稳定CALIB内二者应一致。

判定：DAC码值保持，原始通道继续运行，即CALIB冻结通过。CALIB中的phsm/frqm是保留的KF状态，不要求随原始测量变化，不能用它们计算冻结段频率漂移。

## 3 参考失效及恢复检查

为了优先检查“从CALIB失锁后仍回CALIB”，在上述冻结状态进行。

1. 记录操作时间或最近REFCHK的ms。短时断开GNSS天线，或将便携天线移到接收明显变差的位置；保持OCXO、AX7010、DAC供电不变。
2. 观察日志，直到真正出现 `STATE -> HOLDOVER`。参考失效的判据是代码看到fix无效或sat<4连续5次逐秒检查；GGA过期也会使有效质量失效。天线拔掉后接收机可能继续输出PPS，因此不保证SAMP立即why=5，也不以“拔过天线”作为验收通过。
3. HOLDOVER维持30～60秒，确认 `dac=` 仍为D0，hreset未异常增加。此阶段原始测量可能继续出现，是否可用由质量和门控字段判定。
4. 恢复原天线连接/位置，等待GNSS重新有效。软件要求连续可用的恢复观测，通常会看到恢复提示，再出现 `恢复完成, 回到 CALIB` 和 `STATE -> CALIB`。
5. 回CALIB后再记录60秒，确认DAC仍为D0。不要用KEY1强制切回CALIB代替自动恢复过程。

通过条件：`CALIB → HOLDOVER → CALIB`实际发生，且冻结码值保持。旧的中间提示字符串可能泛称“回TUNING”，应以末尾“恢复完成, 回到…”及实际STATE为准。

如果持续接收不到GNSS失效，或尚未重锁，分别记“本轮未触发”或“恢复待完成”，不能填写通过。不要靠反复按键制造HOLDOVER。GNSS重锁时间取决于接收条件，本步骤没有保证完成时长。

可选补充：在TUNING中再做一次失效/恢复，检查 `TUNING → HOLDOVER → TUNING`。这与CALIB返回检查分开记录；本次最先完成前者即可覆盖CALIB硬锁的重要路径。

## 4 慢环实际参与检查

1. 天线恢复且当前为CALIB后，单击KEY1回TUNING。与上次KEY1操作间隔超过2秒。
2. 保持原天线、供电和接线。状态切换会清慢环窗口，需要重新积累。预留10～15分钟观察，具体以拟合、保护与lag条件为准，不以等待到某一分钟代替有效性。
3. 寻找同一更新拍的SLOWC和CFUSE，例如以下示意字段。

```text
SLOWC ... v=1 ... span=... age=... lag=... src=2 w=0.04... pev=0
CFUSE upd=... wstat_u=... target_u=... used_u=40000 reason=0
[TUNING] ... fmod=2 fsrc=2 fw=40 ... phsg=0 ...
```

以上是字段含义示意，不是预写的测量结果。`used_u=40000`表示实际w=0.04，即4%；状态行fw=40是权重乘1000。实际值可以不同。

候选至少两点、span≥240秒，并满足age≤330秒、lag≤630秒和保护条件，才具备接入条件。实际通过需要src=2并且w>0，CFUSE的used_u>0；只看到v=1或屏幕慢环周期有数字不够。权重从0渐增、出现异常立即降到0是设计行为，不要求权重一定达到10%。

建议记录至少连续12个控制更新拍，报告参与拍数、实际权重范围及退出原因。若期间失效，应保留全过程，不只截取一条最好的日志。

## 5 保存什么以及怎样回填P09

| 项目 | 应交材料 | 记录结论 |
|---|---|---|
| 固件身份 | ELF SHA256、BUILD、KFCONF/CFCONF/FINALCONF原文 | 匹配/不匹配 |
| 正常门控 | 连续1分钟REFCHK/SAMP/NMEA chk及状态行 | 当前样本通过，更新节拍是否正确 |
| CALIB | KEY1事件前后及冻结60秒日志，D0 | 值保持/异常 |
| 恢复 | CALIB→HOLDOVER→CALIB完整事件，操作ms及DAC | 自动回原状态/未触发/未完成/异常 |

把原始DAT及按本包脚本生成的CSV一并归档，操作时间另记简短说明。PC接收终端是调试UART1；代码中的C/T屏幕命令属于UART0，不在COM5里随意发C/T来代替KEY1。

本验收无需独立频率计，也不能替代绝对准确度或稳定度测试。功能检查完成后，如需再采性能，应另开文件并重新积累完整、无故障干预的分析时窗。

## 连续闭环到冻结对照

固定最终 R80、Tu10、Q1e-4 和相位项关配置，使用固定原天线。先连续闭环观察至少 20 min；记录稳定工作点，再通过 KEY1 进入 CALIB，就地冻结 DAC。无需追求固定 1886 码，当前工作点取决于本轮真实状态。

两段连续记录，核对切换前后 DAC 一致。CALIB phsm/frqm 是冻结的 KF 状态，不用于计算冻结漂移，必须用 REFCHK raw×0.1953125。拒绝坏样本、失锁、模型补值和时间/序号断档，采用相同区间长度计算原始 OADEV。

冻结仅说明在 EFC 命令不变条件下的相对参考变化，不能单独分离 GNSS、OCXO、FCLK 或 EFC 动态。漂移方向变化不能排除所有老化贡献，闭环与冻结差异也不能唯一归因于 K_PHASE。硬件故障测试另存文件。
