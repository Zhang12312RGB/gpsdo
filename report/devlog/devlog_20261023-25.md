### 三、控制律分析（16:50 — 17:30）

**关键发现：卡尔曼在长 τ 处失效**

| τ (s) | 原始 pps Allan | 简单块平均 | **卡尔曼 X[1]** | 卡尔曼/块平均 |
|---|---|---|---|---|
| 1 | 6.137 | 5.023 | **0.046** | 0.01× 好 |
| 100 | 0.063 | 0.054 | **0.018** | 0.33× 好 |
| 500 | 0.030 | 0.021 | **0.035** | 1.62× 差 |
| 1000 | 0.011 | 0.012 | **0.027** | 2.26× 差 |
| 1600 | 0.0012 | 0.0009 | **0.021** | 24.6× 差 |

原始数据在长 τ 处一直在下降（无真实漂移），但卡尔曼反而变差，甚至输给简单平均 —— 说明滤波器在「跟踪」而非「平均」，长基线信息被打掉。

**实施：快慢环加权融合（仅测试工程）**

- 权重 = 逆方差加权：`w_slow = var_fast / (var_fast + var_slow)`
- `var_fast = kalman.P[3]`（下限 0.012）
- `var_slow = (√2·σφ/T)² + (漂移率·T/2)²`
- T = 300 s（模型算出的噪声/滞后交叉点，权重峰值 89%）
- 环境变化保护：快慢环连续 20 秒分歧 > 0.5 ppb → 清空慢环窗口

**融合实测（16:51—17:29，36.7 分钟）**

| τ (s) | 融合 | 纯卡尔曼 | 对比 |
|---|---|---|---|
| 1 | 0.0423 | 0.0462 | 好 8% |
| 10 | 0.0580 | 0.0724 | 好 20% |
| 100 | 0.0264 | 0.0180 | 差 47% |
| 1000 | 0.0549 | 0.0275 | 差 2 倍 |

**融合未达预期，定位到更深层的问题**

```
真实频差   mean(pps)   = -0.029 ppb
相位斜率   d(X[0])/dt  = -0.073 ppb      <- 一致
卡尔曼估计 mean(X[1])  = +0.148 ppb      <- 符号相反，差 0.177 ppb
```

**根因**：`Q[3] = 1e-10·T` 小了 4~6 个数量级 → `X[1]` 时间常数超过 2000 s → 40 分钟都收不到真值 → 融合把一个有 0.18 ppb 偏置的值混了进来。

## 2026-10-25 晚间续（17:30 — 20:45）：加权融合与三个隐藏 bug

> 这一段是下午分析的延续：先做加权融合，再把整条链路翻出来审查，
> 最后发现真正的问题既不在算法也不在参数，而在**日志的显示格式**。

### 一、加权融合（测试工程）

**结构**：只在**积分律的输入**上做加权，系统里仍然只有**一个积分器**。

```c
f_ctrl = (1 - w) * kalman.X[1] + w * slow.freq;
control_apply_freq(f_ctrl);        // 和单环同一条增量律，只换输入
```

**权重模型（逆方差）**

| 量 | 表达式 | 说明 |
|---|---|---|
| 慢环方差 | `var_slow = (√2·σφ/T)² + (D·T/2)²` | σφ=5 ns，D=2e-4 ppb/s |
| 快环方差 | `var_fast = kalman.P[3]`，下限 0.012 | 用滤波器自报的协方差 |
| 慢环权重 | `w = var_fast / (var_fast + var_slow)` | 逆方差加权 |

**T 的选取**：噪声项随 T 减小、滞后项随 T 增大，两者交叉在 T≈300 s，
权重峰值 89%。所以 `SLOW_T_FIXED = 300`，不是拍的数。

**三次方年龄衰减**（关键修复）

慢环每 300 秒才更新一次，但融合每秒都在用它。不加衰减时，一个冻结值
会以 89% 的权重连续作用 300 秒，积分器按恒定偏置匀速推 DAC —— 实测
20 分钟把积分器推了 +1.9 ppb（`acc` 1751.1 → 1755.1）。

```c
double u = 1.0 - (double)slow.sec_cnt / (double)slow.T;
if (u < 0.0) u = 0.0;
w *= u * u * u;
```

| 距上次更新 | 权重 |
|---|---|
| 刚更新 | 89% |
| +60 s | 45.6% |
| +150 s | 11.1% |
| +240 s | 0.7% |
| **窗口内平均** | **22.3%**（线性衰减是 44.5%）|

### 二、Q 扫参：卡尔曼的过程噪声

| Q[3] | P3 稳态 | Allan@1s | 结论 |
|---|---|---|---|
| 1e-10 | 冻结 < 1e-4 | — | ✗ X[1] 不收敛，符号都能反 |
| **2e-7** | 1e-4 | **0.0273** | ✅ **最优** |
| 1e-6 | — | 0.0544 | ✗ 偏吵 |
| 1e-5 | 8e-4 | 0.0443 | ✗ 更吵 |

**规律**：P3 稳态约与 Q^0.55 成正比 —— 提 50 倍 Q 只换来 8 倍 P3，
却让估计吵一倍。**2e-7 是这条曲线上的最优点**。

### 三、R 的重标定

| 项 | 改前 | 改后 |
|---|---|---|
| `adaptive_r` 常数项 d | 150 | **50** |
| 典型 R（hdop 1.11 / sat 8.5 / cn0 32）| **124 ns²**（σ=11.1）| **24 ns²**（σ=4.9）|
| 实测 pps 标准差 | — | **5.00 ns** ✓ 吻合 |

**依据**：原来的 150 是 TDC 失效时代（相位量化 50 ns）的估值。
TDC 修好后噪声掉了 10 倍，R 却没跟着改，滤波器因此不信测量。

### 四、P3 的物理下限（动态）

```c
double p_floor = kf->R / (KALMAN_T_EFF * KALMAN_T_EFF);   // T_eff = 160 s
if (p_floor < KALMAN_P3_MIN) p_floor = KALMAN_P3_MIN;     // 兜底 3e-4
if (kf->P[3] < p_floor) kf->P[3] = p_floor;
```

**物理依据**：频率估计的精度受 1PPS 抖动与观测时长限制，
σ_f ≥ √R / T_eff，即 P3 ≥ R/T_eff²。不设下限时 P3 会掉到 1e-4
（σ=0.010 ppb），比物理下限还小 3 倍，卡尔曼增益趋 0，X[1] 冻结。

### 五、全局逻辑审查：三个真 bug

| # | 位置 | 问题 | 后果 |
|---|---|---|---|
| **1** | `slow_enter` | **清零循环写在种点之后**，`X[0]` 恒为 0 | 慢环多出 φ(起点)/T 的偏置 |
| **2** | `enter_state` | 切状态不清慢环窗口 | `X[]` 跨 HOLDOVER，垃圾数据以 89% 权重进融合 |
| **3** | `update_sample_period` | 只在 `(done==0 && active==0)` 门控里调用 | 慢环启动后 T 永久冻结；恢复时若置 1 会永久卡在 1 |

**修复**：
1. 清零移到种点之前
2. `enter_state` 里加 `slow_reset_window()`
3. 调用移到 `kalman_update()` 之后，每个 epoch 都跑

### 六、最隐蔽的一个 bug：**日志格式吞掉负号**

```c
dbg_printf("frq=%d.%03dppb", (int)v, frac_of(v, 1000));
        ↓
v = -0.15  ->  (int)(-0.15) = 0   →  打印 "0.150"  ✗
```

**对 −1 < v < 0 的所有数，负号全部丢失。**
而我们的频率误差、每秒相位增量**恰好全部落在这个区间**。

**后果（严重）**：
1. 所有「`slow` 符号反了」「`frq` 是正的」的判断 **全部是假的**
2. 之前用日志里的 `frq` 算的所有 **Allan 数字都不可信**
3. 排查方向被带偏了整整两轮

**修复**：全部改成毫单位整数，符号安全

```
改前: frq=0.190ppb phs=-9.200ns pps=0.150ns     ← pps 的负号丢了
改后: frqm=190 phsm=-9200 ppsm=-150              ← 一目了然
```

### 七、第二个分析陷阱：`pps=0` 的样本

实测 433 个样本里有 **37 个（8.5%）的 `pps` 是 0** ——
那是 `bsp_meas_valid() == 0` 的秒，既不累加相位也不打印测量。

**如果直接用「全部样本均值」当真值，会被这 37 个 0 稀释**，
算出 +0.003 ppb，看起来像异号，其实是算法错了。

| 口径 | 结果 |
|---|---|
| 全部样本均值（含 0）| −0.0649 ppb ✗ |
| 只用非零样本 | −0.0710 ppb |
| **`psum / 300`** | **−0.0970 ppb ← 真值** |
| **`slow.freq`** | **−0.0970 ppb ← 完全一致** ✓ |

## 经验教训

1. **BD IP 参数会被 .xci 固化** —— 改 RTL 的 parameter 必须同时在 `regen_ooc.tcl` 里强制 `CONFIG.*`，并核对综合日志的 `bound to`。
2. **`set_multicycle_path` 会误命中综合出的 LUT** —— 用 `IS_SEQUENTIAL` 过滤，或改用 `set_false_path`。
3. **「丢弃异常样本」会破坏累加器连续性** —— 改为「修正数值」，环路才能继续。
4. **慢环和快环抢同一个 DAC 必然打架** —— 必须只有一个积分器。
5. **不要只看 1 s 的指标** —— 卡尔曼在 1 s 处好 100 倍，但在 1000 s 处输给简单平均。
6. **理论推断必须用数据验证** —— 「卡尔曼最优所以融合无增益」这个结论，被实测推翻了。
7. **测量工具本身也要自检** —— 一个 `%d.%03d` 的格式问题（对 −1<v<0 丢负号），
   让三轮排查全部走错方向。现在所有量都用整数毫单位打印，并加了
   `acc / psum / dphi` 三个互相印证的字段。
8. **算真值前先搞清楚数据里的「零」从哪来** —— 8.5% 的 `pps=0` 是
   `meas_valid=0` 的正常表现，把它们算进均值会得出完全相反的结论。
9. **一个 bug 会伪装成另一个 bug** —— 「慢环符号反了」「累加器和 pps 差 33 ns」
   「融合让长 τ 变差」这三个"发现"，最后全部指向同一个显示格式问题。
