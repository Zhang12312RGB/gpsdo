## 步骤 2.2 · DAC 换型（19:39）

**做了什么**

```verilog
// spi_dac.v
MCP4921（12 位）→ DAC8531（16 位）
  · 24 位帧
  · 下降沿采样
  · 上电输出 0 V
```

**为什么**

12 位只有 4096 码，按 0.4785 ppb/码算，**一圈只有 1.96 ppm**，分辨率不够细调。

**结果**

DAC8531 16 位，但实际只用了低 12 位（`DAC_MAX = 4095`）—— 见步骤 2.3。

## 步骤 2.3 · `control.h` 参数定型（20:13）

```c
#define DAC_CENTER   1752      /* 锁定点，从标定反推 */
#define DAC_GAIN     0.47852   /* 被控对象灵敏度 g = df/d(dac) */
#define DAC_SCALE    1.91406   /* 环路增益 S = 4g */
#define LOOP_SIGN_DEFAULT  (+1) /* 实测正极性：DAC↑ → 频率↑ */
```

**这些数字怎么来的？**

用 `hwtest_polarity()` 的两点法：

```
HT_DAC_A = 1024   （低测点）
HT_DAC_B = 3072   （高测点，差 2048 码）
每点采 30 个样本，读 0x18（OCXO 边沿差）

g = (dB − dA) / 2048 × 50 ppb
        ↑                 ↑
   斜率(计数/码)      1 计数 = 1 边沿 = 50 ns = 50 ppb
```

**为什么 `S = 4g`？**

```
S = g   → λ = 0，死拍：一步到位，但对估计误差零容忍（会撞轨）
S = 4g  → λ = 0.75，每步收敛 25%，对 g 的标定误差有 4 倍余量
```

# 10-25（周日）上午：TDC 攻坚

**现象**：`0x30` 恒为 0，相位卡在 50 ns 分辨率。

**排查方法**：把 TDC 链路拆成 7 段，逐段用 `hwtest` dump 验证。

## 缺陷 1 · `CARRY4 .S(4'b0000)`

**问题**：

```verilog
CARRY4 u(.S(4'b0000), ...);   // 进位选择全 0
        ↓
CO[i] = DI[i] = 0，进位永不传播
        ↓
全链输出恒定 0
```

**修法**：`.S(4'b1111)`（全选 CI 传播）。

## 缺陷 2 · 温度计解码方向反了

**问题**：找"第一个 1"，但 CARRY4 链在波前到达后是**前面全 1、后面全 0**。

**修法**：改为找"**第一个 0**"。

## 缺陷 3 · 用了同步副本 `pps_sync[0]`

**问题**：

```verilog
tap_in = pps_sync[0];   // 同步后的信号
        ↓
波前和采样【同拍】，走了 0 格
```

**修法**：改用**原始异步引脚** `pps_in`。

## 缺陷 4 · 采样晚一拍

**问题**：波前跑出链尾，`tap` 顶到 512 饱和。

**修法**：

```verilog
每拍抓 tap_now;
在 pps 边沿取【上一拍】的 tap_now;
```

## 缺陷 5 · BD IP 的 `NUM_CARRY4` 固化在 64

**问题**（最隐蔽）：

```
RTL 里写 NUM_CARRY4 = 128
        ↓
但 BD 的 .xci 里 CONFIG.NUM_CARRY4 = 64
        ↓
【综合用的还是 64】
        ↓
三次"512 抽头"实际只有 256 抽头
```

**修法**：在 `regen_ooc.tcl` 里**强制** `CONFIG.NUM_CARRY4 {128}`，并核对综合日志的 `bound to`。

## 缺陷 6 · `set_multicycle_path` 误命中

**问题**：

```
set_multicycle_path 打在【综合出的 LUT】上
        ↓
8 条路径 18~401，WHS −10.176 ns
        ↓
布线 49 分钟不收敛
```

**修法**：删除全部 multicycle，改 `set_false_path`。

## 缺陷 7 · `TAP_PERIOD_REF` 估错 2.8 倍

**问题**：按 62.5 ps/抽头估的 160，实际约 25 ps/抽头。

**标定三次迭代**：

| 次序 | 公式 | 结果 | 每抽头 |
|---|---|---|---|
| 1 | `span + step` | 461 | 21.7 ps |
| 2 | `span + step` | 449 | 22.3 ps |
| **3** | **`span`**（去掉 +step）| **401** | **24.9 ps** |

**最终**：`TAP_PERIOD_REF = 403`。

## TDC 最终指标

| 项 | 值 |
|---|---|
| 单抽头 | **24.8 ps** |
| 每 10 ns 周期 | **403 抽头** |

# 10-25（周日）晚上：加权融合 + 三个隐藏 bug

**数据**：

| τ (s) | 原始 pps Allan | 简单块平均 | **卡尔曼 X[1]** | 卡尔曼/块平均 |
|---|---|---|---|---|
| 1 | 6.137 | 5.023 | **0.046** | 0.01× 好 |
| 100 | 0.063 | 0.054 | **0.018** | 0.33× 好 |
| 500 | 0.030 | 0.021 | **0.035** | 1.62× 差 |
| 1000 | 0.011 | 0.012 | **0.027** | 2.26× 差 |
| 1600 | 0.0012 | 0.0009 | **0.021** | 24.6× 差 |

**推论**：

```
原始数据在长 τ 处一直下降（无真实漂移）
但卡尔曼反而变差
        ↓
说明滤波器在【跟踪】而不是【平均】
        ↓
需要第二条路：慢环做长基线平均
```

## 步骤 4.2 · 加权融合设计

```c
f_ctrl = (1 - w) * kalman.X[1] + w * slow.freq;
control_apply_freq(f_ctrl);        // 只有一个积分器
```

| 量 | 表达式 |
|---|---|
| 慢环方差 | `var_slow = (√2·σφ/T)² + (D·T/2)²` |
| 快环方差 | `var_fast = kalman.P[3]`，下限 0.002 |
| 慢环权重 | `w = var_fast / (var_fast + var_slow)` |
| `T` | **300 s**（噪声项与滞后项的交叉点）|

**关键设计：只有一个积分器** —— 慢环和快环不抢 DAC。

## 步骤 4.6 · 最隐蔽的 bug：日志格式吞掉负号

```c
dbg_printf("frq=%d.%03dppb", (int)v, frac_of(v, 1000));

v = -0.15  ->  (int)(-0.15) = 0   ->  打印 "0.150"  ✗
```

**→ 对 −1 < v < 0 的所有数，负号全部丢失**
**→ 而频率误差、每秒相位增量恰好全部落在这个区间**

**后果**：

1. 所有"`slow` 符号反了""`frq` 是正的"的判断 **全部是假的**
2. 之前用日志 `frq` 算的 **所有 Allan 数字都不可信**
3. 排查方向被带偏了 **整整两轮**

**修复**：全部改成毫单位整数。

```
改前: frq=0.190ppb phs=-9.200ns pps=0.150ns     <- pps 负号丢了
改后: frqm=190 phsm=-9200 ppsm=-150              <- 一目了然
```

## 步骤 4.7 · 第二个陷阱：`pps=0` 的样本

| **`psum / 300`** | **−0.0970 ppb ← 真值** |
| **`slow.freq`** | **−0.0970 ppb ← 一致** ✓ |

# 10-26（周一）：PL 小数化改造

## 步骤 5.1 · 发现核心问题

```
粗计数 LSB = 50 ns（一个 OCXO 周期）
TDC 量程    = 10 ns（一个参考时钟周期）
        ↓
细项只能补 50 ns 的【1/5】
        ↓
粗计数一跳就有 40 ns 漏过去
        ↓
实测 0x00 每秒跳 ±60 ns
```

**这就是"50 ns 跳变"的根源。**

## 步骤 5.2 · 改造方案：给 OCXO 计数加小数位

| 文件 | 改动 |
|---|---|
| **`rtl/ocxo_frac.v`** | **新增** —— 用 `sub` 计数器 + `fine_fraction` 算 `frac` |
| `rtl/counter_measure.v` | 输出 `ocxo_delta_frac` 小数计数 |
| `rtl/phase_error.v` | 粗项改用小数版本 |
| `rtl/gnss_axi_ip_slave.v` | 新增只读寄存器 |
| `rtl/gnss_gpsdo_top.v` | 连线 |

**原理**：

```
原来的输出：
    Δphase = (Δn − 20e6) × 50 ns          ← 只有整数，LSB = 50 ns

新的输出：
    frac = "PPS 落在 OCXO 周期内的哪个位置"     0 ~ 65535
    Δphase = (Δn − 20e6)×50 ns
           + (frac_now − frac_prev)×50/65536 ns    ← 把小数补上
```

**为什么能消掉 ±1 抖动**：

```
情况 A：数到 20,000,000，frac 从 0.2 → 0.3
    Δphase = 0×50 + (0.3−0.2)×50 = +5 ns

情况 B：数到 19,999,999，frac 从 0.2 → 0.3 + 1.0（跨圈）
    Δphase = (−1)×50 + (1.3−0.2)×50 = −50 + 55 = +5 ns
                        ↑
                  【完全一样】
```

        ↓

        ↓

```

```

## 步骤 7.5 · C 版补偿设计

**完整公式**

```
D_ref : 固定 DAC 参考值
g     : 有符号频率增益（ppb/码）
C     : 相对 D_ref 的已知控制相位（ns）

C[n]       = C[n-1] + g × (D_applied[n-1] - D_ref) × dt
phi_ref[n] = phi_measured[n] - C[n]
f_ref      = 对 (实际时间, phi_ref) 做斜率拟合
f_slow_now = f_ref + g × (D_applied_now - D_ref)
```

**两个关键实现细节**

| # | 细节 | 后果 |
|---|---|---|
| **1** | **不能漏掉最后的"加回当前 DAC"项** | `f_ref ≈ −64 ppb`（参考工作点），当前受控频差≈0 |
| **2** | **加回项必须每次控制时刷新** | 若冻结 600 秒，下次 DAC 动作仍会产生已知滞后 |

**实现**

| 文件 | 改动 |
|---|---|
| `control.c` | `control_write_dac()` 统一入口 + `slow_c_dac_changed()` 钩子 |
| `slow_loop.c` | `slow_c_init/dac_changed/observe/sample/current` 一族 |
| `slow_loop.h` | `c_snap_t` 相关字段 |
| `main.c` | 融合段 + 快照 |

**shadow 验证结果**

| 指标 | 离线预测 | **上板实测** |
|---|---|---|
| `fRef` | ≈ −63 ppb | **−64.11 ppb** |
| RMS(fNow − fast) | ≈ 0.12 ppb | **0.122 ppb** |
| `Cns` 积分率 | 64.6002 ns/s | **64.6002 ns/s**（误差 2.7e−13）|

**→ 实现正确，但闭环效果还没测。**

## 步骤 7.7 · 日志格式 bug（当天最后修的）

**现象**

```
fmod=1147680 fsrc=1146088 fw=1200228 fsl=0
        ↑ 全是垃圾值
```

**根因**

```
dbg_printf 是自定义函数，GCC 的 -Wformat 检查不到它
        ↓
格式串加了 4 个 %d，参数忘了加
        ↓
编译 0 警告，运行时读栈上垃圾
```

**修复**

```c
// dbg_uart.h —— 加格式检查属性
void dbg_printf(const char *fmt, ...)
    __attribute__((format(printf, 1, 2)));

// 编译选项
-Wformat=2 -Werror=format -Werror=format-security
```

**验证**：故意删掉 2 个参数 → 编译器报错 `format '%d' expects a matching 'int' argument` ✓

### 实验 3 · 一次被审计纠正的分析

本轮我犯的 4 个错误（已全部改正，见 `report/analyses/analysis_20261028_2125_KPHASE0p002对照.md` 附录 A）：

| # | 错误 | 实际 |
|---|---|---|
| 1 | `K0 = P3/(P3+R) ≈ 4e-5`，判「频率环几乎不工作」 | **P3 是频率方差，R 是相位噪声方差，量纲不同不能相加**。代码是 `K0=Pm[0]/S`、`K1=Pm[2]/S`、`S=Pm[0]+R`。审计重放得 K0≈0.198、K1≈0.00213，**频率支路确实在工作** |

| 3 | 「稳态相位误差 −59→−592 ns」 | v9 的 600 秒里相位从 −1569 恢复到 +44 ns，**仍含明显暂态** |
| 4 | 「v8/v9 冻结段作废」 | **v9 的反向冻结是有效信息**：有偏工作点下固定 DAC 仍有慢变 |

**另外我自己发现的两处**:

* 把 `P3u=390` 除以 1e6 后 `toFixed(1)` 显示成 0.0，误报「P3 塌陷到 0」（实为显示精度，最小 390）

# 附：经验教训（22 条）

## PL 侧

1. **BD IP 参数会被 .xci 固化** —— 改 RTL 的 parameter 必须同时在 `regen_ooc.tcl` 里强制 `CONFIG.*`
2. **`set_multicycle_path` 会误命中综合出的 LUT** —— 用 `IS_SEQUENTIAL` 过滤，或改 `set_false_path`
3. **Verilog 里同一信号被两个 always 块赋值是非法的**
4. **先声明后使用** —— 否则生成悬空的隐式 1 位网线
5. **只用一次的模块会被综合优化掉** —— 优化后信号变成常量
6. **算术右移对负数向 −∞ 取整** —— 会带来累积偏差

## PS 侧

7. **「丢弃异常样本」会破坏累加器连续性**
8. **慢环和快环抢同一个 DAC 必然打架** —— 必须只有一个积分器
9. **不要只看 1 s 的指标**
10. **理论推断必须用数据验证**
11. **门控计数的单位要写清楚** —— 「5 次滤波更新」不等于「5 秒」

## 分析与工具

12. **测量工具本身也要自检** —— 一个 `%d.%03d` 的格式问题让三轮排查走错方向
13. **算真值前先搞清楚数据里的「零」从哪来**
14. **一个 bug 会伪装成另一个 bug**
15. **比不同长度的两轮数据是没有意义的**
16. **单位要反复确认** —— ps/ns/µs 差 1000 倍
17. **自相关要扫全部 lag**
18. **重建数据要理解物理含义**
19. **自定义 printf 家族不受 `-Wformat` 保护** —— 必须加 `__attribute__((format))`

## 协作

20. **外部独立复核价值极高** —— 找出多处事实错误
21. **改动前自动验证** —— 3999 个 PL 向量 + 83 条 PS 状态记录
22. **用户指出 `frac_valid` 是电平** —— 那是最关键的一个 bug
