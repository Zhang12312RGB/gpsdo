### 突破 2：门控重构（v14）

**原来：**

```
if (bsp_meas_valid() != 0 && bsp_pps_ok() != 0) {
    p = read_phase_error_ns();
    main_phase_acc_ns += p;      // 直接累加
}
```

**问题：** 没有检查饱和、撕裂、重复、间隔异常。

**现在：**

```
bsp_snapshot_t snap;
bsp_snapshot_take(&snap);              // 一次读完所有寄存器
why = bsp_sample_classify(&snap);      // 6 种判定
if (why == BSP_Q_OK) { ...累加... }
else { ...跳过，不清零... }
```

**6 种判定：**

| why | 含义 |
|---|---|
| 0 | OK |
| 1 | SAT（饱和）|
| 2 | TORN（撕裂，seq0≠seq1）|
| 3 | DUP（重复，与上次消费序号相同）|
| 4 | GAP（间隔异常 ±0.5%）|
| 5 | NO_MEAS（meas_valid=0 或 pps_lost=1）|

## 三、⭐ 这三天修的 bug

### Bug 1 · t=547 饱和值污染相位累加器（v12 数据发现）

```
现象：t=547 秒，OCXO 计数 4000 万（2 秒量），PL 把相位钳到 INT32_MAX
      = 0x7FFFFFFF × 0.1953125 = 419.4 ms
      PS 没拒绝，直接累加进 main_phase_acc_ns
      → 触发 ±100 µs 保护 → 把相位和 kalman.X[0] 清零
        ↓
后果：前 547 秒积累的 141 ns 相位历史丢失
      后段相位是【从 0 重新积累】的，不是偿还开机历史
        ↓
根因：STATUS_TDC_SAT / STATUS_SAT_FLAG 只写进日志，从不用来拒绝
```

**修复：**

```
① 饱和   raw == 0x7FFFFFFF 或 SAT_FLAG / TDC_SAT
② 撕裂   seq0 != seq1
③ 重复   seq == 上次消费的序号
④ 间隔   偏离标称 ±0.5%
⑤ 无测量 meas_valid=0 或 pps_lost=1
        ↓
任一命中 → 跳过本拍，但【不清零】
```

### Bug 2 · 序号死锁（v15 前发现）

```
只有【好样本】才更新 last_seq
        ↓
100 正常 -> last=100
101 饱和 -> 拒绝，last 仍 100
102 正常 -> 差 2 -> 判 GAP，也不更新 last
103 正常 -> 继续 GAP ...
        ↓
【即使信号恢复，后续样本仍被持续拒绝】✗✗
```

**修复：把两个基准分开**

```
s_seen_seq : 只要 seq0==seq1 就推进（不管样本好坏）
s_last_seq : 只记录成功消费的
        ↓
用 seen 判跳变，用 last 判重复
        ↓
而且 seen 推进【必须在所有拒绝判定之前】
```

**离线验证 7 组序列全过**（含连续 5 拍饱和后立即恢复）。

---

### Bug 3 · 相位连续性缺损（v15 前发现）

```
缺口时「少加了一秒的相位增量」
        ↓
下一个窗口 KF 预测是 X0 + T·X1（含缺失那一秒）
而 z 少了这一秒
        ↓
产生一个假的负新息：1 ppb × 1 s = -1 ns
```

**修复：用当前频率估计补齐**

```
main_phase_acc_ns += f_hold;

其中 f_hold = kalman.X[1]
            + (control_get_last_dac() - s_prev_dac)
              × DAC_GAIN × g_loop_sign;
```

**⚠️ 第二项很重要：**

```
光加 X[1] 是不够的 —— DAC 补偿要到 10 秒节拍才进 KF
而补值每秒都做
        ↓
反例：X[1]=1 ppb，上一拍 DAC 加 1 码，缺测 10 秒
  只加 X[1]：10.0000 ns
  应该补：  (1 + 1×0.47852) × 10 = 14.7852 ns
  差 4.7852 ns → 恢复后假新息 -4.7852 ns
```

---

### Bug 4 · DAC 补偿放在缺口返回之后（v15 前发现）

```
原顺序：
  if (gap) { kalman_predict_only(); return; }   ← 先返回
  ...DAC 补偿...                                 ← 永远执行不到
        ↓
后果：缺口时预测用的是【旧频率】
      每漏 1 码补偿，10 秒相位就差 4.7852 ns
```

**修复：把 DAC 补偿移到任何 return 之前。**

## 五、⭐ 新增经验（23~32 条）

### 门控与状态

23. **「丢弃异常样本」和「保持相位连续」是两件事** —— 前者靠门控，后者靠补偿
24. **门控的基准必须分开** —— 「看到可靠序号」和「接受相位测量」不能共用一个变量
25. **缺口补值要包含所有已知的、尚未进 KF 的输入** —— 漏了 DAC 阶跃就漏 4.8 ns/码
26. **补值必须在任何 return 之前完成** —— 否则预测用的是旧状态
27. **同一份快照必须覆盖所有消费者** —— 相位、序号、有效标志不能各读各的
28. **状态切换后的恢复目标要记下来** —— 写死「回 TUNING」会让 CALIB 的冻结丢失

### 分析

29. **冻结段的 phsm/frqm 不更新** —— 必须用原始通道 raw
30. **含冻结段的数据必须先按 [CALIB] 切分** —— 否则状态混算
31. **比较不同版本时窗口必须一致** —— 且要注意各段自身的收敛点不同
32. **「改善 X%」在单次测量下没有统计意义** —— 要看同一配置跨轮次的离散度

### 数据采集

33. **长测前必须禁用电脑休眠** —— 本轮的 `v19` 122 分钟数据里有 24 分钟是空的（t=7213~8657），
    板子一直在跑（`seq` 7214→8658、`n` 722→867），但 PC 端串口捕获随休眠停了。
    `powercfg /change standby-timeout-ac 0` 应该写进采集清单。

34. **判断"数据丢了"要看三个量**：`ms`（时间轴）、`seq`（测量计数）、`n`（KF 更新计数）。
    三者一起跳 = 板子在跑但没记录；只有 `ms` 跳而 `seq` 连续 = 时间戳异常。

35. **`NMEA drop` 不是日志丢行的证据** —— 那是 NMEA 解析器的正常丢弃计数，
    和串口捕获中断无关。我一开始误判过。

36. **比较不同轮次必须统一窗口长度** —— v16/v18/v19 用各自长度算出"τ=300 离散 7%"，
    统一成 2925 秒后是 **35%**。窗口不同 = 不可比。

37. **重叠差分项数 ≠ 独立验证次数** —— τ=3000 有 614 个重叠差分，但独立段只有 2 个。

38. **编码字段要逐项核对** —— `innov` 是 ×1000 (ns)、`S` 是 ×1000 (ns²)，
    NIS 应该是 `innov²/(1000×S)`，我第一次漏了除 1000，算出 1126598。

39. **算新息相关性必须跳过收敛段** —— 从第 0 拍算是 0.271/0.243，
    从第 60 拍（600 秒）起算才是 0.354/0.220。前者含暂态，会低估相关性。
    X[1] std 同理（0.2006 → 0.1981）。

40. **两个 3000 秒块只构成一组 Allan 差分** —— 即使有 614 个重叠差分项，
    不重叠的独立块只有 2 个，不能说"两个独立的 Allan 估计"。

41. **同一配置的短 τ 也会变** —— v20（Q=1e-4）相对 v19（B）：@1s 改善 21%，@5s 恶化 73%。
    不是单调改善。而且 B 三段自己的 @5s 是 1.71/2.83/2.86，v20 的 2.96 仍在范围内。
    → 不能把轮次差异全部归因于 Q。

42. **追加同配置的段对排除环境漂移帮助有限** —— 应做 `Q -> B -> Q` 交错对照，
    才能回答"切回 B 后是否变差、再切 Q 后是否恢复"。

## 十三、⭐ 新增经验（43~56 条）

### 采集

43. **长测前必须禁电脑休眠** —— v19 有 24 分钟空白，板子一直在跑（`seq` 7214→8658、`n` 722→867），只是 PC 端串口停了。

44. **判断"数据丢了"看三个量** —— `ms`（时间轴）、`seq`（测量计数）、`n`（KF 更新计数）。三者一起跳 = 板子在跑但没记录。

45. **归档要在记录停止后** —— v19 首次归档漏了 83 秒，v22 漏了 75 秒，都是因为文件还在写。

46. **KEY2 连按安全** —— 只调 `screen_page_next()`，不碰状态机。只有 KEY1 有 2 秒双击判定。
    但两次间隔要 >200 ms（`ps_key.c` 队列深度为 1）。

47. **换天线会中断接收** —— 大天线是独立验证段，不能和小天线连续计算，不能跨天线补值。

### 分析

48. **比较不同轮次必须统一窗口长度** —— 各段用自己长度会得到假象。
    **v16/v18/v19/v20/v21 统一为 2925 秒；v22 按段排除 60 秒。**

49. **算新息相关性必须跳过收敛段** —— 前 60 拍（600 秒）是暂态。

50. **重叠差分项数 ≠ 独立验证次数** —— τ=3000 有 614 个重叠差分，独立段只有 2 个。

51. **编码字段要逐项核对** —— `innov` 是 ×1000 (ns)、`S` 是 ×1000 (ns²)，
    NIS = `innov²/(1000×S)`。

52. **`log(R)` 模型预测时必须在原尺度修正** —— `E[R] ≠ exp(E[log R])`。
    用 Duan smearing 或 `exp(σ²/2)`，否则排序会反。

53. **条件数的定义要说明** —— 相关阵用 `sqrt(λmax/λmin)`（2.80），
    直接用 `λmax/λmin`（7.84）会误导。

54. **常量 R 标签不是纯测量噪声** —— 含 OCXO 窗口内变化 + GNSS + TDC + 相关噪声。
    v14 算 46.3，v22 算 40.90，**标签本身有 5 ns² 不确定性**。

### 工程

55. **实测 Q 的收益需要 Q→B→Q 交错** —— 只有一段 Q 时不能排除环境漂移。
    追加同配置的段帮助有限。

56. **快环配置必须一致才能比较慢环** —— v22 是 profile=0，
    慢环配对文件是 profile=1。**三轮都用 profile=1**。
