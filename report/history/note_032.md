## 五、问题清单

### 🔴 问题 1：分数通路仍然完全失效

```
0x00 ≠ 0x18×256 的样本：0 / 900（0.0%）
0x00 = 0 的比例：94.6%
0x00 只取 {0, ±256} 三值
```

**→ 系统仍是纯整数计数，精度步长 50 ns**

**根因（已定位并修复，但未综合）**：
```verilog
tdc_carry.v: fine_valid <= tap_valid && !recip_busy;
→ recip_busy 卡在 1 → fine_valid 永远不来
```
**DBG 行全为 0 就是这个的直接证据：**
```
DBG fine=0 frac=0 diff=0 fracval=0   （900 条，无一例外）
```

**注意**：最初审计怀疑 `recip_busy` 卡住是板上现象，但审计的数字仿真**没有复现**；
我只是把这条链路当作最可能的解释。真实原因需要观测复位、`period_eff`、
`period_d`、`dbusy`、`dstep`、`recip_busy` 才能确认。

---

### 🟡 问题 2：`n` 只到 2，窗口上限实际是 3

```
n 最大值 2，n≥2 比例 14.3%
慢环窗口 300 秒，SLOW_T_MAX = 1000 秒
→ 固定窗口上限 = floor(1000/300) = 3
```

**→ `n` 最多只能到 3，不会继续增长**（这是设计如此，不是故障）。
**但 14.3% 说明慢环启动了又被打断** —— 中止原因需要记录 `innov`、`S`、样本号。

---

### 🟡 问题 3：`dac` 偏中心 −18 码

```
dac = 1734，中心 1752
−18 码 × 0.4785 = −8.6 ppb
```

**→ 说明这颗 OCXO 当前偏 +8.6 ppb（需要负补偿）**。
和上一轮的 +118 码（+56.5 ppb）完全不同 —— **说明 OCXO 的偏置在随温度变化**。
