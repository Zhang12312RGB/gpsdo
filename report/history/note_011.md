## 三、问题 ②：C 候选的有效性

### 3.1 ⚠️ 更正：固定 DAC 不会阻止 C 积累

正确公式：

```
C += g × (D − Dref) × dt

固定 DAC 有两种情况：
  · D ≠ Dref：C 仍随时间线性增长
  · D = Dref：C 保持零，但时间戳和相位观测照常推进，仍能拟合
```

**→ 代码层面已验证：DAC 恒等于参考值、C 恒为零时，仍能得到 n=3、span=600、v=1。**

### 3.2 冻结段没有 SLOWC 的真正原因

```
代码在 CALIB 下主动使 C 观测无效、清空窗口
而且打印函数【只在 TUNING 中调用】
        ↓
【这是实现选择，与 DAC 是否动作无关】
```

### 3.3 C 有效率：同条数比较

| 范围 | v10（中午）| v11（下午）|
|---|---|---|
| **前 55 条 v=1 占比** | **34.5%** | **36.4%** |
| **前 55 条 n 最大** | **2** | **2** |
| 全程 v=1 占比 | 34.5% | 62.0% |
| 全程 n 最大 | 2 | 3 |

**→ 同条数比较差别很小（34.5% vs 36.4%）；v11 全程 62% 是【长时间运行后能积累出有效候选】，不能认定算法或硬件改善。**

## 四、问题 ③：GNSS 与清窗

### 4.1 两次清窗的直接原因（已定位）

| 时刻 | z | 说明 |
|---|---|---|
| **t=1310** | **−5.31** | 触发 5σ 保护 |
| **t=2050** | **−5.19** | 触发 5σ 保护 |

### 4.2 ⭐ 第一次事件的时间线（关键）

| t | R | sat | hdop | frq (ppb) |
|---|---|---|---|---|
| 1300 | **36** | 8 | 1.17 | −0.09 |
| 1302 | 36 | **9** | **0.89** | −0.09 |
| 1309 | 36 | 9 | 0.89 | −0.09 |
| **1310** | **10** | 9 | 0.89 | **−0.18** |
| 1320 | 10 | 9 | 0.89 | +0.26 |

**链条：**

```
t=1302: 卫星 8→9，HDOP 1.17→0.89
        ↓
t=1310: R 从 36 降到下限 10
        ↓
保护门限（5σ）随之收紧
        ↓
约 −20.73 ns 的新息越限
        ↓
z = −5.31 → 清窗
```

**→ GNSS 字段看起来更好（sat↑、HDOP↓），并不保证当时 PPS 噪声立即变小。**

**→ 这比「C 补偿撑不住」更具体；也不建议直接放宽保护来维持有效率。**

**→ 值得优先查 R 模型。**

### 4.3 通信问题并未消失

## 六、能写 / 不能写

### 可以写

```
1. 闭环 DAC=1737 稳定 36.8 分钟，冻结 21.9 分钟全程恒定；
2. 等长 1200 秒窗口下，原始通道闭/冻比值：
     τ=50 1.03、τ=100 0.94、τ=200 0.70、τ=300 0.79；
3. 冻结段全程 OADEV 单调下降到 τ=400 的 0.1008 ppb；
4. FCLK 整数通道 OADEV@100 = 11.08 ppb，比 OCXO 原始大 62 倍；
5. 两次清窗都由 5σ 保护触发（z=−5.31、−5.19）；
6. 第一次清窗前，R 从 36 降到下限 10（sat 8→9、HDOP 1.17→0.89 之后）；
7. 有效 C 候选 137 条，RMS(fNow−fast) = 0.0947 ppb。
```

### 必须注明

```
1. 单轮、单工作点、相对本机 GNSS PPS，非独立外部校准；
2. 重叠 Allan 差分项不是独立重复；长 τ 的普通差分项很少；
3. 「未观察到位劣化」不等于「闭环与冻结完全等效」；
4. NMEA 校验和未验证，drop 仍新增 133；
5. 尚不能认定 K_PHASE、FCLK 或某固定 DAC 工作点是慢变的唯一原因；
6. 有效 C 候选的内部一致性不等于外部验证。
```

### 不能写

```
- 闭环在 τ=300 劣化 2.90 倍（600 秒窗口只有 1 个差分项）；
- 固定 DAC 导致 C 窗口攒不起来（公式不支持，是实现选择）；
- v11 的 C 有效率 62% 说明算法改善（同条数只有 36.4%）；
- GNSS 变好所以通信问题消失（drop 仍新增 133）；
- 慢变已定位到唯一原因。
```
