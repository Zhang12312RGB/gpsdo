## 二、DAC 台阶的正确理解

| 版 | 跳变次数 | **每次幅度** | 码值范围 | 标准差 |
|---|---|---|---|---|
| A | 13 | **±1 码** | 1883~1887 | 1.11 |
| B | 34 | **±1 码** | 1884~1886 | 0.68 |

**两版每次都是 ±1 码，A 只是停留范围更宽**

### 短 τ 的 Allan 几乎完全由 DAC 台阶解释

```
sigma_step(1s) = DAC_GAIN * sqrt[ sum(dDAC^2) / (2(N-1)) ]

A: 估算 0.04686   实测 0.04559   OK
B: 估算 0.07119   实测 0.07086   OK

X[1] 差分与已知控制输入的相关系数:  A 0.992   B 0.997
```

**预测器把 ΔDAC × 0.47852 ppb 加进 `X[1]`，所以台阶直接进估计**
**这种相关性部分来自公式本身，不是 DAC 硬件异常的独立证据**

## 三、慢环的真实参数（修正后）

### 3.1 权重

```
var_fast 下限 = 0.002
var_slow = (sqrt(2)*5/300)^2 + (0.0002*300/2)^2 = 0.00145556
w = max(P11, 0.002) / (max(P11, 0.002) + var_slow)
  = 0.579
```

**实测重建：均值 59.8%，范围 57.9%~67.4%**
**89% 是更早的参数，不能再用**

### 3.2 窗口跨度与滞后

```
slow_loop.c:166   每 300 秒采一点，最多保留 3 点
        |
满窗口跨 600 秒
        |
3 个等间隔点做线性最小二乘 -> 斜率 = 首尾差 / 600
        |
斜率代表窗口中心的频率 -> 生成时就落后约 300 秒
        |
保持到下次采样，还会继续变旧
```

**初版用 T/2 = 150 秒估算滞后，低估了一半**

## 四、机理表述：降级为"相关"而非"证明"

**初版说"正反馈已证明"—— 过强**

**更准确的表述：**

> A/B 支持"现有慢环反馈与中等 τ 波动增加有关"，
> 但尚未唯一辨认是：
> ① 已知控制动作未补偿；
> ② 估计滞后/权重；
> ③ 增益误差；
> ④ 其他动态。

**审计的提醒：有延迟的负反馈也可能产生阻尼变差和往返调整**

**另外**：后段实际 `R` 均值 A≈38.32、B≈24.77 ns² —— **R 算法相同不代表卡尔曼增益相同**

## 五、C 版补偿设计

### 5.1 完整公式

```
D_ref : 固定 DAC 参考值（如启动时的 1752）
g     : 有符号频率增益 = DAC_GAIN * 控制极性（ppb/码）
C     : 相对 D_ref 的已知控制相位（ns）

C[n]       = C[n-1] + g * (D_applied[n-1] - D_ref) * dt[n]
phi_ref[n] = phi_measured[n] - C[n]
f_ref      = 对 (实际时间, phi_ref) 做斜率拟合
f_slow_now = f_ref + g * (D_applied_now - D_ref)
```

### 5.2 两个关键实现细节

| # | 细节 | 后果 |
|---|---|---|
| **1** | **不能漏掉最后的"加回当前 DAC"项** | `f_ref ≈ −63 ppb`（参考工作点），当前受控频差≈0，**不是同一工作点** |
| **2** | **加回项必须每次参与控制时刷新** | 若连它也冻结 300 秒，下次 DAC 动作仍会产生已知滞后 |

### 5.3 一个易错点

```
错误: C(t) = sum g * DAC_j * (t - t_j)     <- 用绝对 DAC 值
        会重复计数

正确: 用 dDAC_j
   或: 用分段保持的 (DAC_j - D_ref) * 持续时间
```

### 5.4 离线验证结果

| 相对快环 `X[1]` 的差异 RMS | A | B |
|---|---|---|
| 原历史慢环 | 0.9411 ppb | 0.2468 ppb |
| **补偿后候选** | **0.1203 ppb** | 0.2779 ppb |

**A 改善 7.8 倍**
**B 没有改善 —— 补偿不是在所有条件下都更优**

## 六、能写 / 不能写（修正版）

### ✅ 可以写

```
1. A/B 单变量对照，唯一差异是 EXP_SLOW_CONTROL；
2. 普通 Allan@100s: 0.3164 -> 0.0431（7.35 倍）；
3. 等长重叠 Allan@100s: X[1] 0.3126 -> 0.0546（5.73 倍），
   原始测量通道 0.4289 -> 0.1477（2.90 倍）；
4. 交叉点在 10~20 秒之间；
5. 两版 DAC 每次跳变都是 +-1 码，A 的码值范围更宽（1883~1887）；
6. 短 tau 的 Allan 主要由 DAC +-1 码台阶解释（估算与实测吻合到 3%）；
7. 慢环权重实测约 59.8%（范围 57.9~67.4%）；
8. 满窗口跨 600 秒，斜率代表窗口中心频率，滞后约 300 秒；
9. 相位：A = -45.06 +- 55.16 ns，B = -8.88 +- 14.18 ns。
```

### ⚠️ 必须注明

```
1. 两轮是顺序采集，不是同时；GNSS 条件与实际 R 不同
   （R 均值 A=38.32, B=24.77 ns^2）；
2. 769 秒窗口下普通 100 秒 Allan 只有 7 个分组、6 个相邻差；
3. 7.35 倍/5.73 倍应注明算法口径，不能当作长期固定倍数；
4. 重叠 Allan 的重叠项并不独立；
5. 短 tau 与相关系数部分来自预测器公式本身；
6. "Allan" 描述的是 X[1] 估计序列或内部测量通道，
   不是独立设备验证的实物输出稳定度；
7. 只有一次顺序 A/B，缺 A->B->A 重复性验证。
```

### ❌ 不能写

```
x 正反馈机理已被唯一证明（只是"相关"，延迟负反馈也可能导致阻尼变差）；
x 关闭慢环后快环自身噪声变大（是 DAC 台阶，不是噪声）；
x A 的 DAC 单次跳得更大（两版都是 +-1 码）；
x 权重 89%（实测 59.8%）；
x 窗口 300 秒、滞后 150 秒（实际 600 秒跨度、约 300 秒滞后）；
x 相位锁在 0 ns（A 在 -45 ns）。
```
